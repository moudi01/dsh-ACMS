# 从 Paperclip bridge 迁移

遵循“旧执行统一暂停后，再导入并恢复”的切换方式。ACMS 不直接改写旧看板，也不代为停止无法确认归属的旧进程。

## 输入与映射

选择包含 `board/` 和 `state/` 的 bridge 根目录。读取 `board/index.json`、各 issue JSON、agents.json，以及 live/state 的状态覆盖与本地评论。只读预览不会创建任务。

| 旧数据 | ACMS |
|---|---|
| 未完成 issue | 暂停任务，保留 identifier、描述和历史状态 |
| done issue | 归档，按明确接受的历史记录满足迁移依赖 |
| cancelled issue | 归档，不满足下游依赖 |
| blockedBy | 同一导入目标下的依赖边；循环依赖拒绝导入 |
| agent | 常驻执行角色；保留旧角色/provider/model 元数据，权限与执行器重新配置 |
| 文档、评论 | 任务详情中的历史内容 |
| 附件 | 原引用；不下载、不搬运附件文件 |
| 旧 Codex 线程 | 不复制；原线程留在旧运行目录 |

历史 done 不产生 ACMS 检查或审查记录。新交付一律按当前项目检查与独立审查执行。所有迁移任务先归入一个迁移目标，后续可按需要拆分新的授权目标。

## 切换流程

1. 在 ACMS 公司设置中添加接管项目。先暂停 ACMS 的其他执行。
2. 打开“迁移旧看板”，输入 bridge 根目录，点击“只读预览”。
3. 统一暂停旧调度和执行；核对旧派发记录、provider 线程、文件修改以及已产生但尚未记录的结果。
4. 重新预览。若仍检测到运行状态或锁，导入会拒绝；缺少终态的旧 dispatch 必须由所有者核对并记录停止证据。
5. 选择项目、填写停止证据，确认接受历史记录，点击“导入暂停任务”。源快照改变会使旧预览失效。
6. 核对文档、依赖、执行器和项目检查，再逐项恢复未完成任务。不要同时重新开启旧执行。

迁移是一次性功能。成功导入后，整个迁移模块从界面移除，迁移 API 关闭；刷新或重启后也不会重新出现，不保留再次导入入口。任务详情中的原始文档、评论、依赖与来源记录继续保留，数据库保留迁移审计记录。导入失败不会移除模块或留下半套任务。增量双向同步不在 0.1 范围内。

命令行只读预览也可使用：

```powershell
node scripts/inspect-import.mjs 'C:\path\to\paperclip-bridge'
```

正式切换前应保留完整旧数据备份。此次开发和验收没有停止或迁移用户的真实旧任务。
