# 交接文本的写入、读回与异常提示

交接正文约定使用 UTF-8；`.md`、`.markdown`、`.txt`、`.rst` 的大小写扩展名均可识别。宿主保存原始字节后在独立、可取消的 worker 中检查可读性信号，不改写内容。普通文档的报告保存于 `artifact.textIntegrity`；按 `acms-delivery/1` 声明的 ZIP 在读取最终条目字节时产生 `archiveVerification.textDiagnostics`。

报告只有 `no-warning`（未触发所列规则）、`warning`（需核对）、`not-inspected`（超出检查范围），**没有内容批准状态**。文件字节 SHA-256、命中计数及最多 12 个行号用于定位，不保存正文片段。任务详情的“文本可读性提示”展示原因；完整产物及报告仍按现有授权范围读取。下游和任务/目标审查使用相同证据，文本摘要与归档摘要共用 16 KiB 提示词预算；ZIP 提示只注入数量，详细报告通过产物 API 按需读取。

这些提示不归类为环境故障，不触发自动重试/返工，不改变用户所选审查流程；未发现异常也不能代替阅读或审查。损坏的文档可能仍是合法 UTF-8，且文件、artifact 和 ZIP 的哈希完全一致。

## 检查规则与范围

- 严格 UTF-8 解码失败，或检测到 UTF-16 BOM：提示核对交接编码约定，不猜测原始编码或自动转码。
- 在有字母/数字的正文中，至少 3 行各出现连续 6 个问号，问号总数不少于 40，且占被检查正文字符至少 12%：提示可能发生字面问号替换。
- 正文中的 Unicode 替换字符 `U+FFFD` 不少于 3 个且占比至少 1%：提示核对解码/写入链。
- 问号和替换字符统计跳过 Markdown 围栏、缩进代码及行内代码，不把纯标点分隔线或问号画当作损坏。不要求含中文，纯英文、混合语言以及普通问句均可通过。
- 每个文档最多检查 1 MiB；每个 ZIP 最多检查 8 MiB 文档字节、保存 100 个文件的异常报告。超过范围或报告数量时记录跳过/省略计数，界面明确显示。超出范围不表示内容有效。

规则是保守启发式，无法判断所有文本的原意。刻意使用密集问号的正文仍可能收到提示；用户应核对源材料，不能把问号自动补写成猜测的中文。源代码、二进制、其他文本格式及嵌套 ZIP 不做此项文本扫描；普通历史 ZIP 未声明归档合同也不自动解析。

## 可复用的 UTF-8 写入方式

使用编辑器的 UTF-8 文件接口，或明确指定编码的 `fs.writeFile(filename, text, 'utf8')`、Python `write_text(text, encoding='utf-8')`、`.NET File.WriteAllText` 配合 `UTF8Encoding`。最后按字节读回，并检查实际归档内条目。

不要把包含 Unicode 的脚本或正文通过编码未知的 shell/native stdin 管道传输。仅在最终 Python `write_text(..., encoding='utf-8')` 指定编码，不能修复此前已经被管道替换为 `?` 的字符。

仓库提供 ASCII Base64 传输工具：

```powershell
node scripts/write-utf8.mjs output.md BASE64_PAYLOAD EXPECTED_SHA256
```

调用方从**原始预期 UTF-8 字节**生成 Base64 和 SHA-256；不要从已经损坏的文件计算期望值来证明它正确。工具先校验规范 Base64、原始字节摘要及 UTF-8，再写入同目录临时文件、同步、读回、替换目标并再次读回。输入验证失败不修改目标，输出记录字节数、摘要及读回结果。目标父目录须已存在；操作遵守执行入口原有文件权限。空文件可通过空 Base64 参数传入。

该约定由公共任务合同传递到内部和配对入口，公共宿主收集链统一检查交付。这里的回归使用模拟执行器和真实本机写入工具，不宣称已对每个真实模型入口完成端到端验收，也不改变它们的 sandbox、审批或会话能力。
