# 项目内协作目录

通过 ACMS 添加项目会在项目根目录建立 `.acms/`。编辑项目或执行任务时也会补建。目录写入失败会明确提示，不会伪称已成功创建。

- `README.md`：协作入口与交接规则。
- `shared.md`：所有者维护的长期约定和材料位置，系统仅首次创建，后续不覆盖。
- `project.json`：项目归属标记，防止不同项目覆盖同一目录。
- `CURRENT.json`：最新快照的路径及内容哈希。
- `snapshots/<hash>.json`：目标、任务关系、依赖、状态、阻塞、最近执行摘要、交接和交付物索引。

每次普通执行将当前目标的快照和所有者说明同步到隔离工作区的 `.acms/context.json`、`shared.md`。执行器先定位自己的任务、父任务和依赖，再读取相关摘要和产物，复用已有进度。任务历史不能扩大当前授权。

重试时刷新协作上下文，不覆盖业务产物。审查使用作者执行时固定的版本，不读取随后变化的所有者说明。执行器不得直接改写固定输入；提交和审查时会校验哈希。

新交接文档应写在普通任务目录，通过 ACMS 提交摘要、产物或阻塞，再由系统更新项目快照。阻塞中的交接也会保留，但不代表交付物已验收。

协作输入不计入业务改动集，也不会被自动合并到 Git。源项目其他未提交改动仍会阻止自动合并。目录和文件不得通过符号链接重定向。

快照仅传递协作记录和产物索引，不自动携带源项目所有未提交业务文件，也不等于完整模型对话。缺失材料或新的审批仍会使相应任务等待。
