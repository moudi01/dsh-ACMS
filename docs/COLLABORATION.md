# 项目内协作目录

通过 ACMS 添加项目会在项目根目录建立 `.acms/`。编辑项目或执行任务时也会补建。目录写入失败会明确提示，不会伪称已成功创建。

- `README.md`：协作入口与交接规则。
- `shared.md`：所有者维护的长期约定和材料位置，系统仅首次创建，后续不覆盖。
- `project.json`：项目归属标记，防止不同项目覆盖同一目录。
- `CURRENT.json`：最新快照的路径及内容哈希。
- `snapshots/<hash>.json`：目标、任务关系、依赖、状态、阻塞、最近执行摘要、交接和交付物索引。

普通工作和返工先读取隔离工作区的 `.acms/context.json` 与 `.acms/shared.md`。新的交接保留原协作快照格式，并在 `handoff` 中记录任务代次、目标合同版本和历史引用。入口最多 16 KiB（序列化后的 UTF-8 字节），优先保留本任务、祖先、依赖、合法返工来源的最近可用检查点、待答问题和产物标识。未找到的关系会标记为材料不可用。

超出入口的记录通过 `handoff.history` 在工作区内按需读取。它指向同一目标的 `.acms/task-history.json`，可按任务 ID 查找保留的近期执行、交接原文与产物索引，并用记录的 SHA-256 核对该 JSON 的原始字节。相同内容复用相同版本和文件。旧代次或旧合同的检查点只以 `historicalCheckpointId` 引用。入口的 `omitted` 统计未内联的条目数量，带省略号的预览可在历史中查看全文。隔离工作区的历史索引不包含会话正文。历史交付也不能证明当前验收通过或扩大授权。

调用执行器时，尝试记录保存交接版本和实际提示词 UTF-8 字节数。工作区元数据另记交接入口及按需历史的字节数，两者均不是模型 token。当前合同、所有者消息、变更通知、验收和有效授权仍通过执行提示词传入，不受交接入口的字节限制。规划和协调保留完整协作快照。

重试时刷新协作上下文，不覆盖业务产物。审查使用作者执行时固定的版本，不读取随后变化的所有者说明。执行器不得直接改写固定输入；提交和审查时会校验哈希。

新交接文档应写在普通任务目录，通过 ACMS 提交摘要、产物或阻塞，再由系统更新项目快照。阻塞中的交接也会保留，但不代表交付物已验收。

协作输入不计入业务改动集，也不会被自动合并到 Git。源项目其他未提交改动仍会阻止自动合并。目录和文件不得通过符号链接重定向。

快照仅传递协作记录和产物索引，不自动携带源项目所有未提交业务文件，也不等于完整模型对话。缺失材料或新的审批仍会使相应任务等待。
