# 智能体会话

在「组织管理 → 角色详情 → 与智能体对话」或「任务详情 → 与负责人对话」打开会话窗口。有正在执行的任务时，角色入口默认选择当前任务；也可切换到独立对话。

- **独立对话**：可在空闲时询问进展、讨论方案。原生 DSH 使用无工具文本流；外部 runner 在独立的临时工作目录回复。聊天不派工、不改变角色职责，也不把回复当成交付验收。
- **即时发送**：原生 DSH 通过 `subagents.sendMessage` 向当前子智能体投递；Codex app-server 通过 `turn/steer` 发送，并核对 `expectedTurnId`。收到执行器回执后才显示“执行器已接收”，不代表模型已处理。
- **中断并续接**：旧版单请求外部 runner 不支持轮内消息。选择此操作会停止原执行，确认进程清理后再使用同一工作副本、任务版本和验收规则续接。不会产生额外返工任务。全局暂停或用户暂停优先。
- **留到下一轮**：只保存方向，不解除暂停、材料阻塞或人工问题。任务没有后续轮次时，消息保持未送达。

独立对话与任务执行使用各自上下文：咨询历史只在独立对话内传递，不并入任务上下文。任务轮次之间是否续接线程取决于执行入口声明的上下文能力，与人员是否留任无关；入口未声明续接时每次执行使用新上下文，但仍会读取 ACMS 提供的协作材料。即时发送和中断并续接都不改变这一边界。

记录按角色与任务隔离；独立对话单独保存。发送请求带稳定 ID，网络重试不会重复投递。服务重启后，无法确认送达的消息标记中断，不自动重发；尚未投递的任务留言继续保留。旧轮次结束后，实时消息不会转发给新轮次。

独立对话与任务共享并发资源。停止回复只取消当前独立对话；关闭窗口不取消回复。回复失败会保留部分文本。若外部进程清理未获确认，该资源槽保留，等待核对。部署脚本也会拒绝在会话执行期间重载。

Codex 原生配对回执可增加 `runtime: "codex-app-server"`。`command` 和 `args` 直接启动本机 Codex app-server；模型及思考深度沿用所有者确认的配置。此协议不声明无工具检测能力。旧配对不会被静默转换，现有 runner 继续兼容。

验证：`npm test`、`npm run build`、`npm run check`、`node scripts/conversation-ui-test.mjs`。协议测试使用模拟 app-server，不消耗真实模型额度。
