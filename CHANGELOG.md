# Changelog

## Unreleased

- Add an owner-facing business activity log (issue #18): `/api/acms/activity` reads the persistent event stream with durable `before`/`after` cursors and project/goal/task filters, and the panel renders short Chinese entries that distinguish the owner, external agents acting on the owner's behalf, managers, executors, reviewers, the scheduler and unknown identities. Event bodies snapshot the acting agent role/name, blocked and delivered events (including manager-coordinated blockers) snapshot the executor, and `goal.succeeded` records the delivered contract version, delivery hash, delivered task/artifact list and only the passed final-review record bound to that delivery, so the panel can open the historical artifact evidence per delivery; later reassignment or role edits cannot rewrite history, and legacy entries without snapshots say so explicitly. `project.saved`/`agent.saved` record whether the record was created or edited (legacy bodies degrade to a neutral wording). Progress/heartbeat/command-audit events stay out, free-form reasons, filter labels and details are redacted (including JSON, escaped JSON, `access_token` and Basic/Bearer authentication text) and bounded before display, older pages never advance the newer-event watermark, load/newer races are discarded by generation, and incremental pages are drained until the newest event is visible. The new Playwright suite verifies attribution, filters, bounded paging without duplicates, reload durability, redaction, empty/new-event synchronization and zero model calls.
- Add review cancellation recovery (issue #20) under the atomic review-subtask model: cancelled task and goal final reviews record actor, time and reason; the delivered task stays completed and the goal stays active with an explicit review state. The panel explains the cancellation and offers a rebuild entry; rebuilding creates at most one new active review for the current delivery, never re-runs delivered work, and does not reuse a stale approval. `reviewSummary` is bound to the current `deliveryHash`/`reviewArtifactHash` and selected by creation order, so a late edit or cancellation of an older-version review cannot override the current delivery; older reviews remain available as separate history, and `review.request` reuses an already-active review instead of duplicating it.
- Add issue #17 display defaults: long text and long lists collapse into bounded summaries with accessible expand/collapse; project/goal/task hierarchy starts collapsed and remembers disclosure per object across data refreshes; completed, archived and cancelled items move to separate searchable/filterable completed lists while completed parents with open descendants stay reachable; lists sort by effective business activity (creation, execution, deliverables, review conclusions, user replies) with progress/heartbeat events excluded. Tasks gain an artifacts/evidence section in the detail drawer, and the activity projection is display-only: statuses, review conclusions, dependencies, scheduler order and goal progress are unchanged.
- Address #17 review findings: attribute attempt/interaction events to their task through the event body or owning record; aggregate deepest descendant activity into parent tasks with cycle protection before tree ordering; only clamp long text when an expand control exists so short text that wraps is never hidden; keep the completed view when jumping from a completed goal; and resolve review-task evidence through its review attempt so goal/task review conclusions appear in the detail drawer.
- Add efficiency time-box warnings (issue #7 slice): new owner policy fields `goalTimeBoxMs` and `timeBoxReserveMs`. At the box the engine stores a checkpoint, creates at most one manager wrap-up coordination task (or a blocked, answerable owner gate when no qualified manager exists), pauses ordinary work dispatch, and resumes it after the wrap-up decision. A budget extension clears the old decision so a later box can warn again. Hard runtime caps and budget interactions are unchanged; the warning never adds budget or bypasses pause, permission, cleanup or review boundaries.
- Address #31 review findings: a capacity failure while creating the wrap-up task keeps a recoverable owner entry without aborting the scheduler tick; legacy policies missing the new fields normalize to 0 so the settings form stays savable; time-box completion refreshes goal delivery (including the final review) when the last work finished earlier; an unconfigured time box stays disabled even when a goal already has extra runtime budget; and when every task was running at warning time the capacity owner entry is created as soon as one becomes attachable (e.g. after a failed attempt returns to ready), while retries never replace or duplicate an existing owner question and emit no events when nothing changed.
- Replace the per-task workflow stage model with goal templates and explicit review sub-tasks (issue #25). Tasks are atomic: no `workflowSnapshot`/`stageIndex`, no `reviewing` waiting state. Goals pin a versioned template (base: 拆分 → 执行 → 最终审查); the template decides whether one goal-level final review is created at delivery, and a review-free template completes without any review call. Reviews are user-requested sub-tasks (`review.request`) that judge only delivered artifacts, acceptance criteria and automatic checks. A rejection records failed evidence and opens manager-led rework; the reviewed task stays delivered and the goal returns to active. Templates are an owner-only boundary and managers cannot choose or add mandatory reviews.
- Add `scripts/legacy-export.mjs` and `src/core/legacy.js` to back up and isolate stage-based data before the model change: consistent `VACUUM INTO` database snapshot, logical JSON export, SHA256 manifest, active-execution guard, and idempotent archival of legacy tasks/goals.
- Address #25 review findings: legacy running attempts are archived as `unknown` with cleanup uncertainty preserved and stop owning scheduler slots; goal final reviews exclude every reviewed author and re-check authorship at acceptance; goals pin a template snapshot so later versions cannot change in-flight review policy; goal-level rework rounds accumulate and, at the configured ceiling or without a qualified manager, open a blocked owner gate that `interaction.answer` can resolve without reopening the delivered task.
- Harden the second review: legacy migration now runs inside `Engine.start` after the scheduler lease is acquired, reconciles every legacy attempt first, and refuses to modify data or start the new scheduler when cleanup cannot be confirmed (the CLI `--force` path is the explicit owner override); owner gates only bind managers that currently hold `task.create` and `task.retry`, so an unqualified manager is asked for again instead of starting a model call that cannot be accepted.

## 0.1.0

First runnable ACMS demo for DeepSeek Harness.

- Native company dashboard, task board, dependency graph, organization/workflow editors, artifact evidence, local blocker responses.
- Persistent autonomous scheduling, bounded temporary agents, independent automatic review, repair/rework loops and durable command/event handling.
- Isolated worktrees, dedicated reviewer verification copies, candidate merge validation and conservative restart reconciliation.
- Optional task-scoped persistent Codex provider with bounded process lifetime and recoverable completion receipts.
- Windows installation/uninstallation scripts, isolated protocol/engine/UI tests and GitHub CI.
